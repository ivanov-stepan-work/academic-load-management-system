# Academic Load Management System

Веб-система для управления учебной нагрузкой и академическими данными в образовательном учреждении.
Проект охватывает полный цикл работы с учебной структурой: пользователи, роли, кафедры, дисциплины,
учебные группы и распределение нагрузки между преподавателями.

Проект разрабатывался как комплексное учебно-прикладное решение с разделением frontend и backend,
REST API и ролевой моделью доступа.

## Демо

### [Открыть демо системы распределения учебной нагрузки](https://ivanovsa.alwaysdata.net/)

## Основные возможности
- ролевая система доступа (администратор, заместитель директора, заведующий кафедрой, преподаватель)
- управление пользователями, ролями и статусами преподавателей
- работа с кафедрами, специальностями, группами и дисциплинами
- распределение и управление учебной нагрузкой
- единый SPA-интерфейс с динамической загрузкой данных
- редактирование данных через боковую панель без перезагрузки страницы

## Архитектура
Проект построен по принципу разделения ответственности:
- Backend реализован на Laravel и предоставляет REST API
- Frontend реализован как SPA на Vue.js
- Взаимодействие между клиентом и сервером происходит через JSON API
- Доступ к маршрутам контролируется middleware на основе ролей

### Backend
- REST API через `Route::apiResource`
- отдельные контроллеры под каждую сущность
- ролевое разграничение доступа (middleware)
- единая точка входа для административных интерфейсов

### Frontend
- SPA на Vue.js
- Vue Router для маршрутизации интерфейсов по ролям
- динамическое построение таблиц и форм
- редактирование данных через offcanvas-панели
- повторно используемые компоненты (Table, Sidebar, EditSidebar)

## Моя роль

- разработка REST API

## Технологии
- Backend: PHP, Laravel
- Frontend: JavaScript, Vue.js, Vue Router, Bootstrap
- Database: SQL
- API: REST
- Auth: Laravel middleware, роли пользователей

## Интерфейсы
В зависимости от роли пользователя доступен соответствующий интерфейс:
- Admin — управление справочниками и пользователями
- Assistant Director — управление учебной структурой
- Head of Department — работа с данными кафедры
- Teacher — просмотр и работа со своей нагрузкой

## Запуск проекта
Проект является учебным и не предназначен для production-деплоя.

Общий порядок запуска:
1. Клонировать репозиторий
2. Установить зависимости backend (Composer)
3. Настроить переменные окружения (`.env`)
4. Подключить базу данных и выполнить миграции
5. Собрать frontend-часть
6. Запустить Laravel-приложение

## Статус проекта
Проект был практически полностью завершён в рамках дипломной работы.
Основной функционал системы реализован и использовался для работы с учебной нагрузкой и справочными данными.

На финальном этапе планировалось добавить экспорт данных (в том числе выгрузку таблиц в Excel).
Базовая реализация вывода данных в HTML-таблицы уже присутствовала, а добавление экспорта в Excel
требовало минимальных доработок (1–2 дня), однако из-за ограниченных сроков дипломного проекта
данная функциональность не была доведена до финальной реализации.

При наличии большего временного ресурса проект мог бы развиваться и поддерживаться дальше
(расширение отчётности, экспорт данных, оптимизация интерфейса).

Проект отражает уровень архитектурных и инженерных решений на момент окончания обучения.
